## Naming Rules

Use:
- `PascalCase.tsx` for React components,
- `kebab-case.ts` or the repository's established convention for modules,
- explicit names instead of `helpers.ts`,
- feature-oriented component directories.

Avoid:
- `NewComponent.tsx`,
- `FinalPlayer.tsx`,
- `utils2.ts`,
- `test123.ts`,
- `temp.tsx`,
- duplicated components with suffixes.

---

## Component Rules

A component should generally have one primary responsibility.

Good:
- `SearchBar`
- `TrackRow`
- `TrackCard`
- `PlayerControls`
- `PlayerProgress`
- `VolumeControl`
- `QueuePanel`
- `MobileMiniPlayer`

Bad:
- one 1,500-line `MusicPage`,
- components that fetch API data and own audio playback and render layout simultaneously.

---

## Production vs Reference Files

Never import from:

`../refe/...`

Production must not depend at runtime on the reference project.

If an asset is legitimately reused:
1. copy the required asset into production,
2. preserve attribution/license metadata if applicable,
3. use the production path.

The deployed app must work with `refe/` excluded.

---

## Git Hygiene

Do not commit:
- `.env`,
- API secrets,
- build output unless repository policy requires it,
- Playwright browser binaries,
- `node_modules`,
- temporary screenshots outside documented audit directories.

Do commit:
- `.env.example`,
- deterministic lockfile,
- test config,
- deployment config,
- docs generated by the reference audit.
